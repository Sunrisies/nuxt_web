# SSR 与性能优化实施说明

## 已实施

- SSR 和浏览器统一经 Nuxt 的同源 API 取数，后端地址迁移到服务端 `NUXT_API_BASE`，兼容现有 `NUXT_PUBLIC_API_BASE`。后台、登录、文件上传与剪贴板仍使用透传代理，不共享公开内容缓存。
- 请求设置超时、不自动重试，保留 HTTP 错误。文章不存在返回 404，公开页面数据故障返回 503，避免空内容 200。后台接口原始状态码、认证头与请求体继续透传。
- 公开列表、分类、标签和归档使用 60 秒服务端 SWR；文章及其 Markdown AST 使用 300 秒服务端 SWR。缓存按后端地址、参数及内容版本隔离，不缓存失败结果。经过 Nuxt 代理的文章/标签/分类/链接写入成功后更新版本，并清理旧缓存。
- 列表去除 Markdown 正文；归档首屏只显示前 100 条，再分批加载。sitemap 在服务端分页读取完整归档，不再限制为前 500 篇，也不再错误地将列表包装对象当数组。
- 文章改成普通 SSR 页面：服务端生成 AST，浏览器使用明确注册的代码块组件。复制与展开可交互，目录组件通过 ClientOnly 使用；正文保持 SSR。上下篇改用文档中的 `/v1/posts/:uuid/prevnext`，与详情并行获取；专用接口缺失时从共享归档摘要缓存计算上下篇，其他失败时省略，不再逐篇查询 200 条列表。
- 移除按路径重建布局和重复的回到顶部实例；分页使用正常内部链接，并以响应式参数更新数据。页面过渡缩短为 150 毫秒，支持减少动画偏好。
- 标签统计使用统一 composable，消除相同 async-data key 对应不同接口的问题。页面标题不再重复站点名。
- 登录弹窗按需加载；时光轴图表在客户端、桌面尺寸且进入视口时异步加载。移除 VueUse 手动分包及不再使用的 Nuxt Content 模块，正文解析仍使用 MDC。
- 导航图标增加尺寸、解码与懒加载；导航分类观察改用 IntersectionObserver。哈希静态资源预生成 gzip/Brotli 并设置长期不可变缓存。
- 新增 `/api/health` 存活检查和 `/api/ready` 后端数据就绪检查。Docker 构建与运行统一 Node 24，锁定 pnpm 并使用冻结锁文件安装，排除本地 `.env`。
- 部署先在临时端口验证候选实例，再切换固定端口；失败时恢复旧容器。固定端口切换仍有短暂间隙，真正零停机需要网关切流。

## 资源变化

同一统计口径：生产 HTML 声明的入口及预加载 JS，单位 KiB，gzip 为本地压缩估算，不是完整浏览器网络下载和执行时间。

| 页面 | 优化前原始 JS | 优化后原始 JS | 优化前 gzip | 优化后 gzip |
| --- | ---: | ---: | ---: | ---: |
| 首页 | 671.6 | 624.6 | 223.5 | 209.1 |
| 博客列表 | 740.5 | 693.4 | 243.0 | 228.4 |
| 时光轴 | 1295.3 | 774.9 | 431.4 | 257.5 |
| 文章 | 659.2 | 710.6 | 217.7 | 237.4 |

时光轴首屏声明 JS 减少约 40%；首页减少约 7%。文章页恢复 Vue 交互及代码高亮，需要增加约 51 KiB 原始 JS，相比之前不工作的服务端正文是明确的功能成本。服务端输出规模由原有约 46 MiB 降至约 40 MiB；该数字是构建目录规模，不代表容器常驻内存。

已实际确认静态 JS 请求协商 gzip，响应包含 `Content-Encoding: gzip` 和 `Cache-Control: public, max-age=31536000, immutable`。动态 HTML 压缩仍交给部署网关；本次没有修改未知的线上 Nginx/CDN 配置。

## 运行与限制

参考 `.env.example` 设置 `NUXT_API_BASE`、`NUXT_API_TIMEOUT` 和 `NUXT_PUBLIC_SITE_URL`。正常启动使用 `pnpm dev`；生产使用 `pnpm build` 后启动 `.output/server/index.mjs`。

缓存和失效按当前单实例架构实现。多实例部署前应配置共享 Nitro cache 存储；如果直接在后端写入、绕过 Nuxt 代理，内容按 TTL 更新，可另接发布 webhook 做即时失效。本次没有为动态 HTML 建立整页共享缓存，以确保故障和发布更新语义一致。

初次实施时后端就绪检查为 502，首页正确返回 503。随后已完成网络排查并恢复本地真实 API 连接：就绪检查、首页、真实文章、分页、标签、归档、时间轴及 sitemap 已验证；专用上下篇接口实际返回 404，已增加摘要缓存回退。详情见 `backend-connection-verification.md`。这些验证仍不代表线上用户性能或并发能力，LCP、INP、CLS 需要另行测量。

仓库全量 ESLint 仍有 52 项既有问题，位于本次未修改的后台、登录及剪贴板文件，主要为显式 `any` 和 import 顺序。本次没有通过放宽规则掩盖这些问题。用户已有的 `bun.lock` 保留。

如果后端文章详情 GET 同时更新浏览量，启用缓存后应将浏览量上报拆成独立接口，避免依赖每次 SSR 取文章计数；本次未修改未知的后端计数行为。

## 后端源码核验及会话接入

已读取 `Sunrisies/server` 提交 `daa9383137f5a6da32a8a3daf32600287de591ea`：鉴权实际是 JWT `access_token` Cookie（HttpOnly、Secure、SameSite=Strict、Path=/），没有 `/auth/me` 或 `/auth/logout`。Nuxt `/api/auth/session` 提取 JWT 中的用户 UUID，仅用于向已有的受保护 `/v1/users/{uuid}` 发起查询；签名和过期验证交给后端，不信任本地解析结果。只返回 id、uuid、user_name，并禁止缓存。后台路由及页面头部通过该接口验证状态；不再用 localStorage 判定登录。

`POST /api/auth/logout` 校验 Origin 并清除浏览器 HttpOnly Cookie，页面同步退出。此措施无法撤销已经复制出的 JWT，立即撤销需要后端增加令牌撤销机制。真实账号登录仍未验证。源码另发现公开注册默认授予 SUPER_ADMIN，以及 JWT secret、token 写入日志，需要后端优先修复（本轮未修改后端）。
