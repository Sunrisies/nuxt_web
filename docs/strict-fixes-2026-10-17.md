# 严格复查问题修复与本地验收

日期：2026-10-17。范围为此前复查的三个P1路径及七牛对象与数据库确认不一致问题。仅更新本地Nuxt生产副本与Rust release，不部署线上服务。

## 1. 非法分页参数

旧 `/api/v1/uploads` 服务层现在拒绝page=0、limit=0、limit>100和页码乘法溢出，返回400后才允许进入SeaORM分页；增加ID作为同一上传时间下的稳定排序依据。管理员实际请求非法参数后，服务仍正常，health/ready均200。未用故意使进程崩溃的方式验证旧版。

## 2. 公开缓存的数据库权威版本

新增 `public_content_revision`，通过 `src/sql/content_revision.sql` 的PostgreSQL触发器，在文章、分类、标签、文章标签关联及链接变更的同一数据库事务内更新版本。文章阅读计数不触发该版本，回滚不改变已提交版本。

公开 `GET /api/v1/posts/content-version` 返回无内容信息的epoch+counter，并声明no-store。Nuxt每个请求从后端读取权威版本，将它加入公共数据/Markdown AST缓存键；同一请求复用版本读取，观察到版本变化时清理旧blog缓存。数据库提交后发起的新请求会采用新缓存键，不依赖写入是否经过某个Nuxt实例。提交前已开始的读取可按此前已提交状态完成。

版本读取失败时返回502/504，不回退到可能已下线的缓存；就绪检查也验证该依赖，liveness仍独立。代价是公开数据请求新增轻量版本查询，不能把本次结果描述为SSR容量提升。HTML缓存及缓存容量限制仍是后续独立优化。

## 3. 新旧上传入口及删除统一

`/api/v1/images/upload` 与旧 `/api/v1/upload` 统一执行图片校验、存储、图片记录及上传记录确认；保留各自原有成功返回结构。图片元数据和上传元数据在同一事务内写入，失败不再忽略。

启动时幂等补齐历史image/*上传记录到图库。旧 `/api/v1/uploads/{uuid}` 删除也会导入尚未关联的历史资源，并委托相同的引用检查与真实删除流程。草稿、发布、下线、正文、HTML和封面引用均受保护，409时不删除对象。云端删除失败保留数据库记录并返回失败，删除调用在线程池执行。两个上传入口的Nuxt代理超时统一为60秒，媒体删除为30秒。

## 4. 上传确认与持久化补偿

新增内部 `media_upload_jobs` 表。接收、异步写盘和受限图片处理完成后，先持久化计划对象key，随后才调用七牛。SDK工作及数据库确认由独立任务持有，HTTP请求取消不取消确认任务。

确认事务同时写images、uploads并删除任务。服务端重试以对象key幂等确认，可处理提交响应不确定；不会因重试重复插入两份元数据。确认失败时，补偿清理先检查是否已有已提交元数据，避免误删实际已确认的对象。

清理状态持久化为cleanup，云端删除失败保留任务供后台每30秒批量重试。运行任务每15秒续心跳；pending任务1小时没有心跳后视为可恢复。清理开始后禁止迟到任务发布元数据。清理完成保留cleaned回执7天，用于处理迟到完成/重复清理，之后移除。

这是可恢复的最终一致性流程，不是跨七牛和PostgreSQL的原子事务。数据库不可用时无法安全确认提交状态，任务会保留，等待数据库恢复；进程被强制结束后也可能需等租约过期再恢复。正式部署必须保留数据库任务表并持续运行恢复任务。

## 部署与备份

新增数据库结构沿用现有启动初始化模式：启动账户需具备创建表/函数/触发器权限。正式环境应先以迁移账户应用结构、授予运行账户所需权限，再启动服务。必须先升级后端，再升级依赖content-version的新前端；旧后端不具备该接口时新前端会拒绝就绪。

本地迁移前数据库备份位于仅当前用户可读的 `.backups/before-strict-fixes.dump`，旧二进制/前端保留为 `web-server-before-strict-fixes`、`frontend-before-strict-fixes`。不要只回滚单侧，也不要在未确认新数据和待处理任务时直接覆盖恢复旧库。

完整Vue应用类型检查仍受原工具链问题影响，本轮仅对服务端TypeScript进行检查，不将生产构建等同于完整应用类型检查。
